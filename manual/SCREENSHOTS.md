# Screenshot inventory and verification

All images are real bounded captures from WSJT-SWISS 3 on Windows. No images were generated or reconstructed. The application uses English; native Windows controls follow the operating-system language.

Unchanged settings and auxiliary windows were captured from v3.0.2-swiss1 (63910a). Contest frequencies, default highlighting, import and submission were captured from the feature build f104bbbee. The final generation-failure checks use ac1a2d211. The UI appearance is unchanged by the dialog-acceptance fix. Submission details, rejection, uncertain receipt, generation errors and the optional export screens were refreshed from ac1a2d211.

The ManualDemo profile and the isolated Qt test-mode ManualImport profile contain fictitious station details (HB9AAA, JN47, operator@example.com). The import source is a fictitious WSJT-X - Demo profile in the Qt test directory. No actual station settings were imported or modified.

Portal screenshots use only http://127.0.0.1:8765/submit, served by tests/manual/uska_portal_fixture.py. Receipt screenshots do not represent a USKA entry or a real email. The received QSY popup uses an offline waveform generated by ft8sim with message HB9AAA.BV174; no RF was transmitted and no reply button was pressed.

The reference covers all application form types, all Settings tabs, and representative native chooser and message-box families. Error text can vary with the radio, operating system, filesystem and portal response. The reference explains the response rather than attempting to reproduce every possible hardware failure. Separate applications (MAP65/QMAP and sample utilities) are outside this WSJT-SWISS window inventory.

## Behavioral checks

- Existing profile: both Swiss FT4 frequencies added once; selecting 3.580 MHz changes the band to 80 m. 7.055 MHz is available for 40 m. Existing frequencies remain present.
- Existing highlighting: an unchecked New Call on Band choice is retained. Reset Default 1 enables it. A new imported profile with no saved highlighting also starts with it enabled.
- Empty contest log: submission blocked before station-details/file generation.
- Automatic generation: callsign-named .cbr under the profile Cabrillo directory; two QSO lines at 3580/7055 kHz, correct UTC date and canton exchanges, and CATEGORY-MODE: DIGI.
- Local portal: warning cancellation and rejection stop before the declaration POST; success posts declaration=1 and displays the receipt. Unexpected final confirmation displays the uncertain-receipt advice.
- Generation failure: a demo-only file occupying the Cabrillo directory path reproduces the failure. The old UI prematurely accepted the dialog; removing its generated accepted-to-accept connection fixes that. The automated regression covers failed/cancelled generation and explicit success.
- Live final-build failure check: dismissing the directory-creation error leaves the details form open; restoring the directory and retrying creates a separate file without overwriting the earlier file.
- Manual backup export: .cbr filter, profile log-directory default, successful export to a folder containing spaces and an accented character, remembered successful export directory, and file-picker cancellation leaves the form open without another write.
- Windows build/test run 43619902711: eight tests, zero failures, including test_export_cabrillo_dialog.
- Local Markdown links and screenshot paths checked; four language guides describe the same submission workflow.
